# Episode 39 Production Blueprint — Building the RFQ Technical Package and Approving First Production

status: PRODUCTION BLUEPRINT COMPLETE
season: Season 4 — Quality, Suppliers and the Reality of Scale
lifecycle: LVP → SVP

## Listener transformation
Before: treats RFQ as drawing + quantity + delivery date.
After: builds a technical package that communicates configuration, CTQs, material/process requirements, inspection/test, documentation, packaging, traceability and change rules, then defines evidence for first-production approval.

## Narrative hook
Three suppliers quote the same drawing and return three different assumptions about material state, inspection, packaging and special processes. The RFQ was commercially complete but technically ambiguous.

## Teaching flow
1. RFQ objective: quote the same technical problem.
2. Configuration baseline: drawing/model/BOM/spec revisions.
3. CTQs and functional acceptance.
4. Material/process/special-process requirements.
5. Measurement, inspection, test and reporting expectations.
6. Traceability, certificates, records and packaging/handling.
7. Tooling/NRE ownership and change rules.
8. Deviations, substitutions and approval authority.
9. First-production approval: representative source/process/configuration evidence.
10. Production release, open gaps and reapproval triggers.

## Core framework — RFQ Technical Package
`Scope/configuration → requirements/CTQs → material/process → tooling → inspection/test → documentation/genealogy → packaging/logistics → deviations/change → first-production evidence → approval authority`.

## Listener tools
- RFQ Completeness Check.
- First Production Approval Matrix: claim, required evidence, source/process representation, result, deviation, owner and release decision.

## Common mistakes
- drawing-only RFQ;
- supplier assumptions not captured;
- first article accepted without production-intent process/source;
- certificates collected without linkage to actual requirement;
- tooling or inspection ownership unclear;
- changes allowed by email without effectivity control.

## Source/evidence backlog
PPAP/FAI or customer-specific first-production frameworks must be named and applicability-controlled. No universal approval package or sample count should be claimed.

## Closing handoff
