# Source Notes Contract — Hardware-to-Production Podcast

status: CANONICAL PUBLICATION-PACKAGING CONTROL
version: 1.0
created: 2026-09-10
backbone_change: NO — publication layer only

## 1. Purpose

Define the minimum source-note/show-note evidence package required between script review and PODCAST READY.

The source notes must let a technically serious listener or reviewer answer:
- Which external sources support the consequential engineering premises?
- Which claims are our synthesis rather than source statements?
- Which standards/editions are current as of the source check?
- What applicability limits matter?
- Which numbers/cases are illustrative versus factual?
- What source re-check is required immediately before publication?

Source notes are not a bibliography dump. They are the public-facing evidence map for the episode.

## 2. Entry gate

Create source notes only after:
1. claim/source lock exists;
2. script outline exists;
3. full script draft exists;
4. technical/editorial script review identifies the actual claims retained in narration.

Do not include sources merely because they appeared during research if the final script does not use the supported premise.

## 3. Required sections

Every episode source-note pack must contain:
1. episode/source-pack metadata;
2. short source-use statement;
3. primary/authoritative sources actually used;
4. claim-to-source map for consequential external premises;
5. standards/current-status register where named standards appear;
6. applicability/transfer limits;
7. internal synthesis/tools explicitly identified as ours;
8. illustrative/fictional content declaration;
9. quantitative-data declaration/checks;
10. publication re-check list;
11. unresolved blockers, if any;
12. gate status.

## 4. Source hierarchy

Prefer:
1. regulator/government/standards body/original investigation;
2. official industry-body technical source;
3. peer-reviewed or authoritative technical publication;
4. manufacturer/company primary source for product-specific facts, clearly attributed;
5. secondary source only when it adds necessary context and the primary source is unavailable/inadequate.

Do not use source count as a quality metric.

## 5. Standards rule

For each named standard record:
- exact designation;
- title;
- edition/year/current publication status as checked;
- applicability/scope relevant to episode;
- whether clause-level text is actually verified;
- revision-watch state if an update is active.

If only public metadata is available, source notes must explicitly say:
`standard identity/status/scope verified; clause-level normative content not used`.

## 6. Claim mapping rule

Do not list every sentence.
Map every consequential external premise and all P0/P1 sourced claims.

Suggested fields:
`Episode claim/statement → source ID → evidence class → exact section/location → applicability → spoken use / show-notes-only`.

V6 synthesis does not need an external citation merely to appear, but its factual premises must be covered by the relevant source records.

## 7. Case-study rule

For real cases, source notes must preserve source ownership:
- regulator/investigation fact;
- company-reported fact;
- allegation/settlement wording where relevant;
- our interpretation;
- our transferable lesson.

No source-note wording may strengthen causation beyond the source.

## 8. Quantitative rule

For every engineering-significant number state:
- source or `illustrative`;
- units;
- date/population/configuration if factual;
- formula/check record if calculated;
- whether uncertainty/sensitivity affects the conclusion.

Editorial exercise quantities/times may be labeled `editorial guidance, not an engineering threshold` rather than numerically verified.

## 9. Public vs internal detail

Source notes may contain more precise technical metadata than the spoken script.

However:
- avoid reproducing copyrighted standards text beyond necessary short quotation limits;
- do not publish licensed standard content in the repository;
- cite designation/location instead;
- keep internal production controls identifiable but do not present them as external authority.

## 10. Publication re-check

Immediately before final publication/recording lock, re-check any source that can materially change:
- active standard revisions;
- regulations/jurisdictional requirements;
- recall/investigation status;
- company/current-product status;
- current guidance revisions;
- URLs/locators needed by show notes.

Evergreen engineering guidance does not need artificial re-checking unless edition/status changed.

## 11. Gate statuses

Use:
- `SOURCE NOTES OPEN`
- `SOURCE NOTES COMPLETE — BLOCKERS REMAIN`
- `SOURCE NOTES COMPLETE — FINAL PUBLICATION RECHECK ONLY`
- `SOURCE NOTES COMPLETE — READY FOR PODCAST READY GATE`

Do not mark PODCAST READY solely because source notes are complete.

## 12. Final relationship

`Source Lock → Script Outline → Full Script → Script Review → Source Notes → PODCAST READY Gate`.

The final PODCAST READY gate must verify the script actually matches the reviewed/source-noted version and that no late editorial change introduced a new unsupported claim.
