# Pilot Batch 01 — Episode Research Pack Production Pilot

status: ACTIVE
purpose: Validate the post-freeze podcast production system before opening all 68 episode packs.

## Pilot set

1. A1 — From an Idea to Engineering Requirements
2. A4 — Choosing Prototype Technologies Without Trapping the Product
3. Episode 1 — The Product Works. Why Can't We Manufacture It?
4. Episode 23 — DFMEA, PFMEA, Control Plans and Quality Gates
5. Episode 29 — Capacity, Bottlenecks, Takt Time and Line Balance

## Why these five

The pilot intentionally spans different production and editorial risks:

- **A1** tests founder/DEV entry, systems thinking and requirement discipline without assuming manufacturing knowledge.
- **A4** tests prototype-shortcut logic, expiration conditions and bridge-to-production thinking.
- **Episode 1** tests the principal entry point for teams with a working prototype.
- **Episode 23** tests a standards/quality-heavy practitioner pack with high P0 verification burden.
- **Episode 29** tests equations, units, assumptions, capacity reasoning and numerical QA.

## Pilot success criteria

The batch passes only if the five packs demonstrate that the production workflow is repeatable.

### Technical
- claim register exists;
- P0 claims are identifiable;
- source-vs-synthesis distinction works;
- applicability can be expressed clearly;
- quantitative examples can be independently checked where applicable;
- no episode contradicts V1 global invariants.

### Audience
- primary listener is obvious;
- DEV/LVP/SVP position is obvious;
- prototype shortcuts have expiration conditions where relevant;
- listener action/tool is tangible;
- entry without the full 68-episode sequence is possible.

### Navigation
- season placement is useful;
- prerequisites are limited;
- recap burden is reasonable;
- next/deep-dive links are meaningful;
- topic-track tags add value rather than duplicate structure.

### Production workflow
- one episode template can serve foundation, practitioner and quantitative episodes;
- unresolved research is visible;
- Podcast Ready cannot be accidentally claimed before evidence gates close;
- pack structure is efficient enough to scale to the remaining 63 episodes.

## Pack maturity states

`RESEARCH PACK OPEN → CLAIM SET STABLE → EVIDENCE VERIFIED → TECHNICALLY REVIEWED → SCRIPT READY → PODCAST READY`

The pilot does not require all five episodes to be scripted before the process is evaluated. It does require enough evidence work to demonstrate that the contract is practical and does not hide technical gaps.

## Pilot metrics

For each pack track:

- number of core claims;
- P0 / P1 / P2 count;
- verified-source ratio;
- unresolved normative claims;
- number of worked examples;
- number of listener tools;
- number of prerequisites;
- estimated recap burden;
- technical-review findings;
- packaging defects/rework.

These are process-improvement metrics, not episode-quality scores.

## Batch decision

Possible outcomes:

### PASS
The template/workflow can scale with minor editorial refinements.

### PASS WITH REPAIRS
No backbone change required, but packaging/template/source workflow must be improved before opening all remaining packs.

### FAIL / BACKBONE GAP
A repeated technical gap or contradiction is discovered that cannot be solved by evidence or editorial packaging. Trigger controlled post-freeze backbone change review.
