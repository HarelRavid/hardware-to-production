## Authority order
Claim Lock → Source Register → Technical Review → Script Outline → Production Blueprint → Season Continuity/Backbone → Supporting files → Existing Full Script Draft as reference only.

Never resolve a conflict by guessing.

## Speakers
SPEAKER A — Lead Host / Systems Engineer.
Owns mechanism, decision logic, canonical tools, evidence/applicability, and lifecycle translation.

SPEAKER B — Practitioner / Challenger.
Technically competent. Pushes on cost, speed, supplier reality, process practicality, inspection and “why not the simpler shortcut?”

B must carry real technical content, not act as a student.

## Season 2 writing rule
Teach:
mechanism → failure/variation → design tradeoff → production evidence → decision.

Do not create an encyclopedia episode.

Use visuals in PRODUCTION NOTES when spatial/process detail is better shown than spoken.

## Technical truth rules
- Use only claims authorized by the Claim Lock.
- Preserve material/process/application boundaries.
- Do not invent generic process values, tolerances, temperatures, times, strengths, density limits, cure windows, qualification criteria or break-even volumes.
- Do not strengthen guidance into requirements.
- Do not transfer aerospace/automotive/customer rules outside their scope.
- Internal Hardware-to-Production tools must be presented as our working tools, not external standards.
- If a new consequential claim seems necessary, place it under REVIEW FLAG — NOT FOR AUDIO.

## Dialogue requirements
1. Open with the approved illustrative hook.
2. State the listener transformation naturally.
3. Follow the Outline beats.
4. Execute the primary listener tool on the worked example.
5. Use concise callbacks to earlier episodes instead of re-teaching.
6. Include DEV/LVP/SVP only where the manufacturing decision changes.
7. Correct the listed misconceptions naturally.
8. End with one concrete listener action.
9. End with the exact handoff to the next episode.

## Standards/source handling
Do not read URLs, clauses or citation metadata aloud.
Name standards only when identity/status materially improves the lesson.
Keep dense edition/revision material in production/show notes.
