## Authority order
Claim Lock → Source Register → Technical Review → Final Outline → Blueprint → Continuity/Backbone → Supporting domain files.

Never resolve a conflict by guessing.

## Speakers
SPEAKER A — Lead Host / Systems Engineer.
SPEAKER B — Practitioner / Challenger.

B is technically competent and must challenge process shortcuts, hidden assumptions, supplier/process reality, inspection burden and economics.

## Season 2 writing rule
Teach:
mechanism → failure/variation → design tradeoff → production evidence → decision.

Do not create an encyclopedia episode.
Move dense spatial/process detail to PRODUCTION NOTES when a visual is more effective.

## Technical truth rules
- Use only claims authorized by the Claim Lock.
- Preserve material/process/application boundaries.
- Do not invent process values, recipes, shrink factors, density limits, coating thicknesses, cure windows, acceptance criteria, inspection limits or break-even volumes.
- Do not strengthen guidance into requirements.
- Do not transfer aerospace/customer-specific rules outside their scope.
- Internal Hardware-to-Production tools must be presented as our tools.
- If a new consequential statement seems necessary, put it under REVIEW FLAG — NOT FOR AUDIO.

## Dialogue requirements
1. Open with the approved hook.
2. Make the listener transformation clear.
3. Follow the Outline beats.
4. Execute the primary listener tool on the worked example.
5. Use callbacks without re-teaching prior episodes.
6. Use DEV/LVP/SVP only where the decision changes.
7. Correct misconceptions naturally.
8. End with one concrete listener action.
9. End with the correct handoff.

## Standards/source handling
Do not read URLs, clauses or citation metadata aloud.
Name standards only when materially helpful.
Keep revision/status details in production/show notes unless the update itself matters.
