## 3. Two-character narrative strategy

Canonical roles:
- Oz — Lead Host / Systems Engineer.
- Rona — Practitioner / Challenger.

Season-wide rule:
Rona must not be a novice caricature. B represents the competent engineer/founder/operator who pushes back on unnecessary rigor, asks what changes in practice, and exposes the failure mode behind abstract guidance.

Recommended recurring dynamic:
- A introduces the decision problem.
- B challenges cost/complexity/necessity.
- A narrows the claim using evidence/applicability.
- B tests it against a practical example.
- A and B jointly execute the listener tool.
- B summarizes what would change Monday morning.

This keeps technical depth conversational without weakening rigor.

## 6. Terminology lock

Use consistently:

- DEV / LVP / SVP — internal lifecycle lens.
- claim / evidence / applicability envelope.
- definition / as-built-as-run / evidence.
- prototype representativeness.
- production intent — claim-specific, not one binary state.
- industrialization / NPI — responsibility/evidence system, not fixed org role.
- product readiness / manufacturing readiness — separate but interacting.
- CTQ — use as practical shorthand; do not imply one universal taxonomy.
- measurement adequacy before capability.
- rework adds history.
- accepted sustainable throughput — later-depth concept only.
- effectivity — practitioner concept; not attributed to a standard unless separately locked.

Avoid synonyms that create competing frameworks.
