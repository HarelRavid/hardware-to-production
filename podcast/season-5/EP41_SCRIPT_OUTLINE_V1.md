## Listener promise
Decide whether automation is the right intervention now, and identify when it would freeze instability, hide process knowledge or attack the wrong constraint.

## Cold open
[ILLUSTRATIVE] A team automates an operator-sensitive step that still changes every engineering build. The robot repeats the same unresolved defect with less flexibility to diagnose it.

## Beat 1 — Automation is not a maturity badge
Claims: EP41-C01
Sources: W4-S14/S15.
Question: What problem are we solving?

## Beat 2 — Mechanism before machine
Claims: EP41-C02/C05
Reuse Wave 02 risk/process evidence.
Guard: automation can amplify unresolved mechanisms; do not claim it always worsens them.

## Beat 3 — Constraint before headcount story
Reuse Wave 03 EP29.
Labor pain can matter, but verify whether the step limits accepted system output or solves safety/ergonomics/quality/cost.

## Beat 4 — Measurement first
Claim: EP41-C03
Source: W4-S18 + Wave 02.
Robot repeatability is not process capability.

## Beat 5 — Intervention ladder
Claims: EP41-C04
Manual → fixture/poka-yoke → assisted → semi-auto → full automation.
Use Sentinel connector example.

## Beat 6 — Change volatility and tacit operator rescue
Ask what operators are compensating for and whether that variation is understood enough to encode.

## Beat 7 — Safety, recovery and maintenance hard stops
Claims: EP41-C06
No exact standard clauses; unresolved hazard/recovery/maintenance ownership blocks release.

## Listener tool — Automation Readiness Gate
stable configuration → understood mechanism → adequate measurement → known constraint/loss → simplest intervention → safety/recovery → economics → automate/defer.

## Misconceptions
- robot can do it = robot should do it;
- repeatability = capability;
- labor saving = business case;
- full automation is more mature than semi-auto;
- manual rescue should be ignored because automation will remove it.

## Closing action
For the automation project currently under discussion, write the exact physical/business problem in one sentence. If the proposal still makes sense when the robot/vendor name is removed, continue.

## Handoff
EP42 asks whether the justified automation concept is economically justified over its full lifecycle.
