# Episode 41 Production Blueprint — When Not to Automate

status: PRODUCTION BLUEPRINT COMPLETE
season: Season 5 — Automation, Data and the Connected Factory
lifecycle: LVP → Ramp → SVP
maps_to: MASTER_WBS 8.1

## Listener transformation
Before: treats automation as the natural next maturity step once volume rises.
After: can identify when automation would freeze instability, hide missing process knowledge or create an expensive constraint, and can define the evidence required before automating.

## Narrative hook
A team automates a manual assembly step that still depends on operator judgement and frequent engineering changes. The cell becomes slower to change, harder to debug and produces the same defect more consistently. The problem was not insufficient automation; it was premature automation.

## Teaching flow
1. Automation is a process-design decision, not a maturity badge.
2. Start from stable product definition, CTQs and current failure mechanisms.
3. Separate labor pain from true system constraint.
4. Check process stability, measurement adequacy and accepted throughput first.
5. Identify design/change volatility and expected product lifetime.
6. Evaluate manual rescue and tacit operator knowledge.
7. Decide whether mechanization, fixture improvement or semi-automation solves the problem first.
8. Define explicit readiness evidence and exit conditions.
9. Reassess after bottleneck movement or product change.

## Core framework — Automation Readiness Gate
`Stable requirement/configuration → understood process physics → capable measurement → known losses/constraint → repeatable manual/semi-manual method → economic need → change risk → safety/maintainability → evidence → automate / defer`.

## DEV / LVP / SVP
- DEV: optimize learning; avoid irreversible automation unless it is itself the experiment.
- LVP: fixtures, assisted tools and selective automation may create more value than a full cell.
- SVP: automation should support demonstrated process control, throughput, quality, maintenance and lifecycle economics.

## Listener tools
- Automation Readiness Gate.
- Do-Not-Automate Checklist: unstable design, unstable process, inadequate measurement, unknown constraint, low utilization, high change frequency, weak maintenance ownership, unresolved safety or recovery logic.

## Common mistakes
- automating because competitors do;
- replacing headcount without modeling system losses;
- buying equipment before the process is stable;
- treating robot repeatability as process capability;
- automating an inspection method that is itself unreliable;
- ignoring recovery/changeover/maintenance.

## Source/evidence backlog
Automation-readiness recommendations are synthesis/backbone guidance. Any safety requirement, machine directive, robot/cobot standard or sector-specific qualification rule must be exact-edition/applicability controlled before script authority.

## Closing handoff
Once automation is technically justified, Episode 42 asks whether it is economically justified across the real lifecycle rather than only on a labor-saving spreadsheet.
