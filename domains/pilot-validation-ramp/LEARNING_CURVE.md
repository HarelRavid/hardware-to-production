# 5.5 Learning Curve

status: Researching
provenance: [GNR]

## Scope
Separate genuine process learning from temporary engineering support, selection effects, design changes, supplier changes and increasing automation during pilot/ramp.

## Learning objects
- unit/build sequence
- operator/team experience
- cycle time
- touch labor
- engineering support time
- defect rate
- FPY/RTY
- rework
- setup/changeover
- downtime
- material loss
- process parameter adjustments
- design/process revision

## Learning mechanisms
- operator familiarity
- improved Standard Work
- fixture/tool refinement
- parameter optimization
- defect prevention
- supplier/process stabilization
- improved material presentation/logistics
- automation/inspection improvement

## Engineering principle
Improvement over consecutive builds is not automatically a learning curve. The underlying product/process configuration must be tracked so that learning is not confused with redesign, cherry-picking, added expert labor or changed suppliers.

## Questions
1. Which metric is actually learning: labor hours, cycle time, yield, cost, or all of them?
2. Is improvement retained when engineering experts leave the line?
3. Does learning transfer across operators/shifts/sites?
4. Are gains caused by process learning or by product/design changes?
5. Has the standard method been updated to capture the learning?

## Decision objects
### D-RAMP-LEARN-001 — Define learning metric and baseline
### D-RAMP-STD-001 — When should a learned improvement become released Standard Work?
### D-RAMP-TRANSFER-001 — Has learning become organizational/process knowledge rather than individual skill?

## Integrity rule
Do not fit or claim a universal learning-rate exponent without a defined dataset, stable scope and evidence.
