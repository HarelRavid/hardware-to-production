## Core synthesis chain
Question / decision -> relevant Knowledge Objects -> claims/evidence -> conflicts/assumptions -> case evidence -> engineering interpretation -> transferable lesson -> episode structure -> show-note sources.

## Core principle
A case study is not an anecdote chosen to fit a lesson. The lesson must remain bounded by the evidence, context and mechanisms demonstrated by the case.

## Case-study object
- case ID
- organization/product/process context
- time period
- source set
- engineering problem/decision
- initial state
- actions/changes
- observed outcome
- likely mechanisms with evidence level
- confounders/alternative explanations
- quantitative evidence where available
- lessons
- non-transferable/context-specific elements
- linked WBS domains
- linked Claims/Decisions
- podcast mapping

## Cross-industry principle
Automotive, medical, aerospace and industrial-equipment examples are sources of methods and lessons, not automatically normative templates for unrelated industries.

## Master decision object
### D-POD-SYN-001 — Is this case/claim sufficiently evidenced and appropriately scoped for teaching in an episode?

Output:
- usable lesson
- supporting claims/evidence
- disputed/uncertain points
- applicability limits
- listener value
- episode placement
- remaining research gaps

## Integrity rule
Do not present post-hoc storytelling as established causation.
