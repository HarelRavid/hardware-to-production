## 3. Workflow findings

### Finding W1-P01 — shared-source locking works
NASA requirements/verification/CM guidance supports multiple episodes without duplicating source research, provided claim meaning/applicability are mapped per episode.

### Finding W1-P02 — source lock should precede full script
The script stage introduced no new P0 claims because the claim/source boundary was fixed first.

### Finding W1-P03 — standards can remain useful without forcing normative narration
ISO/IEC/IEEE 29148 and ISO 10007 are useful current-reference anchors, but the episode does not need unsupported clause-level language to teach the engineering mechanism.

### Finding W1-P04 — technical review must test absolutes
A7 review caught an important possible overstatement: `one passing unit proves nothing` would be technically false. The final draft instead distinguishes configuration-specific verification from process/population capability.

### Finding W1-P05 — editorial review must protect terminology
A1's `working requirements set` terminology is preferable to loosely using `baseline` for a highly fluid DEV artifact. This type of edit is small but important because later A8 gives `baseline` a configuration-management meaning.
